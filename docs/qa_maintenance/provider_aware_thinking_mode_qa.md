# Provider-Aware Thinking Mode QA

## Scope

Validates that thinking controls are model-route scoped, fail closed for unknown
routes, and never silently ignore an explicit unsupported selection.

## Matrix

| Scenario | Expected |
|---|---|
| Shipped-default or models.dev effort (`o3` on `openai` from the shipped record, `gpt-6-luna` on `opencode-go` from models.dev) with selection `high` | Chat Completions body includes top-level `reasoning_effort=high`; sync/stream parity for non-stream fields |
| Model with no reported set (no layer answers) and an explicit selection | Turn admitted with the provider default; the selection passes through unchanged and no thinking field reaches the wire |
| Null / cleared selection | Provider default by omission; no invented `balanced` at the wire, and no provider-instance capability lookup is required for deterministic/standalone routes |
| Capabilities switch from legacy to `thinking_mode_source=model` on an unchanged route | Composer reloads the model snapshot immediately instead of remaining `Unavailable` |
| Legacy thinking controls in an isolated composer | Legacy list remains renderable without requiring model-scoped `SessionCubit` context |
| Legacy `fast`/`balanced`/`deep` when mapped option exists | Migrates to `low`/`medium`/`high` only when present in descriptor |
| Legacy alias when mapped option missing | Cleared with correction reason `thinking_option_unavailable_for_route` |
| Anthropic manual vs adaptive model | Manual emits `budget_tokens`; adaptive emits `thinking.type=adaptive` + effort; never both |
| Budget option metadata (declared `anthropic_budget`/`google_thinking` budgets) | Every advertised budget option publishes the exact positive `budget_tokens` its settings or provider-reported declaration resolves; models.dev reports no budgets, so no budget tier is invented; Off, effort, level and toggle options carry none |
| Explicit Anthropic budget that fits below the request `max_tokens` | The selected budget is emitted verbatim as `thinking.budget_tokens`; no remap |
| Explicit Anthropic budget the request `max_tokens` cannot honour | Actionable rejection while the body is built (`ThinkingWireSerializationException`), zero provider requests; the budget is never silently replaced by `max_tokens - 1`. A declared ceiling of `1`, `0` or a negative value leaves no room for any positive budget and is rejected the same way, while an absent `max_tokens` leaves the selected budget unchanged |
| Local thinking-wire rejection reaches the runner | Blocked `invalidRequest` notice titled `Thinking option not supported` carrying the local reason; no provider-response or contact framing, no provider identity |
| Null/omitted selection with native default metadata present | Wire stays provider default by omission: no explicit request value unless an ordinary explicit selection is sent. `default_option_id`/`is_provider_default` dispatch only when that option is explicitly selected, and a Client that auto-admits its own route's known native default sends it as exactly that ordinary selection; for an existing conversation that admission is display/next-send only and is never written as a preference |
| Budget metadata round-trip | `budget_tokens` survives option and descriptor serialization; a non-positive, fractional, non-finite or otherwise malformed count is absent, never truncated or fabricated, and never fails the round-trip |
| Gemini budget vs level | Nested `thinking_config` uses budget or level only |
| Aggregator OpenRouter | Keeps the aggregator `reasoning` envelope; a finite effort set declared by the gateway's own model metadata is authoritative for that exact route, otherwise the `openrouter` models.dev entry, otherwise `unknown` — see [OpenRouter Reasoning Discovery QA](openrouter_reasoning_discovery_qa.md) |
| Ollama missing probe versus valid negative probe | Missing/malformed evidence is `unknown`; a valid capability list lacking `thinking` is `unsupported`; no name-based options |
| Ollama Boolean declaration | Exactly declared On/Off choices and member Boolean default; sync/stream `think` remains Boolean; omitted Default emits no `think` |
| Live native evidence older than the 5-minute TTL | Validated On/Off/default facts are retained under the matching route/config revision: On sends `think: true`, Off sends `think: false`, Default omits `think`; no degradation to unknown or rejection |
| Explicit probe failure or stale cache on a native route | Resolution stays `unknown` and explicit selection is rejected with `thinking_capability_unknown`; aged evidence never bypasses failure/invalidation markers |
| Config or credential revision change with aged native facts | Cached descriptor is invalidated, the fresh revision is reassembled, and selection is rejected while that revision has no native evidence |
| Failed refresh then config/credential revision change | Failure provenance is not cleared by the revision alone; resolution stays `unknown` and selection is rejected |
| Successful live refresh after a failed probe | Failure provenance is dropped, `source` returns to `live`, and On/Off/default resolve with typed native wire |
| Typed thinking-selection rejection at turn admission | Terminal error response delivered only after the owned work item commits `cancelled`, then the turn completes normally; unrelated queued work stays `queued` and restorable |
| Stale rejection whose work item already lost ownership | No terminal response, no in-flight clear, no turn-completion signal (no busy release or queued-work drain); the newer durable owner, its bound identity, and its queued work are untouched |
| Ollama level declaration | Exactly declared native string choices/default; a native string `off` stays a string, not Boolean `false` |
| Malformed native values/default or untyped capability list | No fabricated options/defaults; unresolved evidence stays unknown |
| Codex exact native metadata | `supported_reasoning_levels` and optional member `default_reasoning_level` survive discovery/cache/resolution; malformed or foreign-model metadata is not finite evidence |
| Valid native levels without a default | When a lower layer (shipped record regardless of route class, models.dev serving vendor, then canonical) declares a default for the same exact id that is one of the winning options, it fills the default with `default_source` provenance; otherwise no default is guessed. With no default the Client chip shows the selected `Provider default` state and the wire remains omission |
| Custom / generic compatible route without exact model evidence or declaration | `unknown`; no selector inventing OpenAI effort |
| OpenCode Go unknown model with `supports_reasoning_output=true` | Control remains unavailable; reasoning output alone does not invent selectable effort |
| Explicit empty `thinking_mode` session preference | Client transmits the present empty field; daemon clears persistence and emits `thinking_mode: null`. The clear is route-scoped: `update_session_preferences` routes it through `ThinkingRouteSessionSync.revalidateAndApplySession(selectionId: null, restorePreserved: false)` for the session's (or the same request's target) route, so the route preference store records provider default and neither the next same-route turn nor a later switch back to that route restores the previous stored choice. A non-empty set that the route offers takes the same path with `selectionId` set to the normalized value, so a later route round trip restores that explicit choice; an option the route does not offer keeps the row-only write and is corrected to provider default at the next turn's admission. Repeated reads of `TurnRouteState.effectiveThinkingMode` within a turn record one correction only and never re-stamp `corrected_at` |
| Client `thinking_mode_source=model` | Composer uses model/`thinking_control` options only; empty list does not fall back to `balanced` |
| Client exact model descriptor identity | Resolves thinking descriptors using exact model ID; preserves catalog namespaces (`VendorA/model` vs `VendorB/model`), case (`CaseModel` vs `casemodel`), and variant markers (`~`, `:`); strips only transport-owned provider-instance prefixes (`provider-1/`) with exact boundaries |
| Client unsupported descriptor | Visible, disabled `No control` chip; no menu is offered and the chip never claims the model cannot reason |
| Client initial descriptor load | Shows `Loading...` until the authoritative snapshot arrives |
| Client authoritative unknown descriptor | Visible, disabled `Not reported` chip; does not invent selectable controls, never renders a level or a synthetic `Default`, and is never conflated with the `Unavailable` transport state |
| Route revision mismatch | Stale session descriptor ignored |
| Explicit model refresh on mounted route | Composer updates options, default, and capability revision without route change or restart |
| Model refresh invalidating current selection | A valid explicit choice is retained; an invalid or removed selection is repaired only to the route's known valid native default, or cleared to the selected `Provider default` state when the refreshed route declares no default. The control never disappears |
| Model refresh removing descriptor or marking unsupported | Transitions visibly to the disabled `Not reported` (removed evidence) or `No control` (unsupported) chip; the control never disappears |
| Failed, late, or cross-device model update events | Retains prior validated authority on failure; ignores foreign device/provider events |
| Model/provider switch invalidating selection | Preference cleared + correction event |
| Daemon restart with queued turn | Revalidates persisted selection before provider call |
| Five-layer authority, real adapter wire (`layered_thinking_authority_test.dart`) | Settings override wins over a shipped default. Provider-reported item metadata wins over a shipped default. Shipped defaults win over the models.dev serving vendor. The models.dev `canonical_model_id` entry fills only when the vendor entry has no `reasoning_options`. No layer → `unknown`. The real Test Home OpenCode Go list regains its pre-regression controls (`deepseek-v4.1-flash`/`deepseek-v4-pro` off/low/high/max default high, `glm-5.3` low/high/max default max, `glm-5.1` off/on default on, `kimi-k3` low/high/max default max, `kimi-k2.6` on/off default on, `grok-4.6` low/medium/high/xhigh default high), with every option on the Go wire. models.dev gains are kept (`gpt-6-luna`, `claude-haiku-5-5`, Qwen 3.8, Gemini Argon contributor) |
| Custom route, model-only declaration per API mode | `openai_chat_effort` and `toggle_effort` declarations reach the Chat body; `anthropic_adaptive` reaches the Messages body; a declaration whose wire is incompatible with the actual mode resolves `unsupported` with no options |
| Failed model-list refresh with a persisted supported model-owned descriptor | Reconstruct under current configuration/mode/revisions; only matching supported `models_dev`/`config_override` facts survive (cache row remains `cache_stale`). Endpoint-declared controls stay route-owned and unresolved until a successful refresh |
| OpenRouter disable envelope | Admitted zero Google budget, typed false toggle and canonical effort `none` serialize as `reasoning: {"effort": "none"}` without contradictory `enabled: true`. Google level `off`, malformed effort/level, negative Google budget, non-positive Anthropic budget and unsupported directives reject before dispatch instead of being dropped. Positive admitted values keep their exact nested fields; Default omits `reasoning` |
| Declared Google levels and zero budget | Canonical `minimal` parses from the shared level vocabulary. Declared zero budget resolves to `GoogleBudgetDirective(0)`, reaching `extra_body.google.thinking_config.thinking_budget: 0` on Google and the documented disable envelope on the aggregator, never an invented `thinking_level: off` |
| Declared known defaults and Boolean kwargs semantics | Config and endpoint defaults remain descriptor metadata; null/empty/whitespace selection omits even with `default_option`, while an explicitly selected default dispatches exactly. Boolean kwargs declarations reject both Boolean values behind canonical effort-tier labels; genuine on/off and exact supported effort mappings retain meaning |
| Failed model-list refresh with live-probe-derived evidence | Descriptor becomes `live_probe_failed` `unknown` and selection is rejected with `thinking_capability_unknown` until a successful refresh rebuilds it |
| Documented selection ids are never silently remapped | Selecting the advertised Gemini `minimal` level reaches the wire as `thinking_level = minimal`; legacy alias migration applies only to ids the route does not advertise |
| Failed refresh, unchanged authority | A cached `supported` model-owned descriptor is re-derived from current authority under the same revision, so the documented controls survive a transient endpoint failure and still resolve to their typed directive |
| Failed refresh after override removal, revision change or mode change | The removed/changed model-only override, a bumped config revision, or an incompatible route/API mode fails closed (`live_probe_failed` unknown) instead of resurrecting stale controls; the reconstructed-offered descriptor is never re-advertised |
| Failed refresh with authoritative failure or live evidence | Already-invalidated descriptors (`live_probe_failed`, `cache_stale`) and native/live probe descriptors stay `live_probe_failed` unknown until a successful refresh |
| Failed refresh with endpoint-declared controls | a control declared only by the endpoint's own discovery metadata is route-owned evidence and is never reclassified as intrinsic support: it becomes `live_probe_failed` unknown until a successful refresh revalidates it |
| Failed refresh with a changed credential revision | a bumped credential revision fails closed exactly like a config revision change; the stale supported descriptor is not retained |
| Client provider-default disclosure (Plan 77 / Task 77K) | The thinking menu offers exactly the declared native options and no synthetic `Default` row or chip. The declared native default is disclosed only as a provider-default hint line below its own row inside the expanded menu, next to any budget annotation that row declares; the closed chip, the persistent interface and every other row show no such claim. An exact declared option id — including a reserved-looking string — always dispatches itself |
| Client display order | The menu renders the declared choices strongest-first, i.e. the declared order reversed for display only: exact native ids, the finite option set, dispatch values and native metadata (including a legacy device list) are unchanged, and no strength ladder, sort heuristic or provider remapping is introduced |
| Client route without thinking transport | `supports_thinking_mode_change=false`, or a legacy-mode device whose `thinking_modes_list` is empty, renders a visible disabled `Unavailable` chip and offers no menu; the control is never removed from the composer |
| Client provider-default entry (removed by Plan 77 / Task 77K) | The thinking menu offers exactly the declared native options and no synthetic `Default` row or chip selection. The declared provider default survives only as the menu-only hint row annotation described above. An exact declared option id — including a reserved-looking string — always dispatches itself |
| Client known native default auto-admission | With no valid explicit choice, the route's declared default that still matches a current declared option is admitted as that option through the real composer selection path and sent as that exact value; the chip and checked row name it like any other option |
| Client declared default unknown or absent (user rule 2026-10-21) | The chip shows the localized selected state `Provider default` (`thinkingModeProviderDefaultSelectedLabel`), never "Not selected" or an empty selection; no thinking field is dispatched, no preference is written, no tier is guessed and no `Off` is fabricated. The menu still lists only the declared options |
| Default fill for `glm-5.2` on OpenCode Go | Options `high`/`max` come from the Go models.dev entry; the default `max` comes from the shipped record (`default_source: shipped_default`). The chip shows `Max` for a session with nothing stored, and the next send carries it without writing a preference; an unset agent-side selection still omits the field |
| Explicit pick across restarts (`thinking_pick_restart_persistence_test.dart`, `conversation_input_cubit_test.dart`) | An explicit `max` for `glm-5.2` on Go survives an agent restart (including one before models.dev hydrates), a capability-revision change and a catalog reload; startup recovery keeps it and the next turn dispatches `reasoning_effort: max`. After a Client restart that first restores the conversation as an identity-only placeholder, the conversation's stored pick (not the device-level last pick) becomes the next-send value once its summary arrives, without a device write |
| Client explicit choice versus the declared default | A valid explicit choice, including an exact `Off`, always wins; resolution never overwrites it and never re-dispatches an already admitted value |
| Client route/conversation isolation | A route or conversation change never writes another route's or conversation's value; a superseded snapshot response dispatches nothing, and only the resolved current route admits its own native default |
| Client same-route conversation switch | A newly selected conversation on an unchanged route admits its own declared native default when it has no valid explicit choice, while a conversation holding a valid explicit choice (including `Off`) keeps it and never receives its sibling's admitted value. The write is dispatched only under the composer's own active-conversation ownership, so a composer that has not adopted the new conversation yet writes nothing and defers to its own ownership change |
| Client token-budget preset without a declared count | The menu annotation still identifies the preset as a token budget; no token value is invented and no effort-like label stands alone for it |
| Client fractional declared budget (`budget_tokens: 1024.5`) | Parsed as absent metadata, never truncated to `1024`, and never re-serialized as a real count |
| OpenCode Go `gpt-6-luna` | No shipped record; the `opencode-go` models.dev entry gives `supported` `none…max` with no default; with no entry it is `unknown` and the turn runs with the provider default. Its per-model protocol is Responses (`provider.npm @ai-sdk/openai`), which Sanad does not yet route (live-r1 D3) |
| Moonshot `kimi-for-coding` | Provider-reported `/models` metadata (`supports_reasoning`, thinking type `only`, `think_efforts` `low/high/max` default `max`) yields a `supported` effort descriptor with no Off and default `max`; each option sends `reasoning_effort`. A names-only item stays `unknown`. A carried-over selection the route does not offer falls back to provider default with a route-scoped correction |
| ChatGPT / Codex reasoning route (`gpt-6-luna`) | Descriptor is `supported` via parsed `supported_reasoning_levels`; emits `ResponsesReasoningDirective` on wire; provider-specific capability is not inferred from shared model identifier |
| Multi-route switching with persisted preferences | Switching between routes with preferences (e.g. `o3` with `high`) through unsupported or unknown routes preserves the valid choice in route-keyed preferences without choice clearing; switching back restores the valid choice and wire directive |
| Clamp of an unoffered explicit selection | Clamps to the nearest lower offered level (`xhigh`→`high`, `medium`→`low` on DeepSeek `off/low/high/max`); never escalates and never falls to Off/none; with no lower level (`low` or `medium` on GLM-5.2) it is rejected with `thinking_option_unavailable_for_route` |
| GLM-5.2 serving route (live acceptance 106b r2 G1) | On OpenCode Go the shipped record (`routes: first_party`) does not supply options: Go's models.dev entry answers with `high`/`max` and no Off, its missing default is filled with the shipped `max`, and efforts send `reasoning_effort` only; Off is rejected before dispatch. On first-party Z.AI the shipped `off`/`high`/`max`, default `max`, still applies and Off sends `thinking: {type: disabled}` |
| Provider 400 rejecting the thinking field | The same request is retried exactly once without the field and only the rejected selection value on that route+model is remembered for that session (in memory); a later different selection on the same route is still sent, and a warning records that the requested level was not applied. A second rejection is not retried, a 400 about anything else is never retried, and other sessions keep sending their field |
| CLI pre-dispatch thinking rejection (live acceptance 106b r2 G3/G4) | `sanad run --thinking-mode <id>` accepts the product option ids including `off`/`on`. A selection the route rejects before dispatch exits `1` with `status: failed` and `error: thinking_option_unavailable_for_route: …`; the daemon logs it at INFO without a stack trace. A stray positional next to `--brief-file` is named in the exit-2 error instead of a generic mutual-exclusion message |
| Client opening/hydrating a conversation (live acceptance 106b r2 G2) | Opening a conversation never sends `update_session_preferences` and never writes the device thinking preference. The control shows the stored selection, or the route's declared native default when nothing valid is stored, and that value is what the next send carries (in memory only). Only an explicit menu choice writes (`route_thinking_mode_real_preference_test.dart`) |
| DeepSeek official wire on OpenCode Go (`opencode_go_deepseek_v41_thinking_regression_test.dart`) | Shipped `native_toggle_effort` record wins over the effort-only models.dev entry: Off sends `thinking: {type: disabled}` with no effort; `low`/`high`/`max` send `thinking: {type: enabled}` plus the exact `reasoning_effort`; default `high`; omission sends nothing |
| Carried-over turn selection on a route without that option (Client `create_session` + `think` carrying a hidden last-used `high` onto `kimi-for-coding` "Not reported" or `gpt-6-luna` "No control") | The turn value equals the preference persisted before the turn, so it is a carried-over preference: the turn completes with `UseProviderDefault()` (no thinking field on the wire) and a route-scoped correction records the dropped value. A fresh explicit turn value that differs from the persisted preference is still rejected before any provider call; a valid explicit selection on a supported route is honored unchanged |
| Stale saved route preference before turn admission | When an upstream capability revision removes a previously selected option (e.g. `low`), an incoming turn without an explicit selection catches the stale selection during `TurnRouteState.effectiveThinkingMode`, records bounded correction feedback (`optionUnavailable`), and falls back to provider default (`null`) rather than aborting admission |
| Legacy session on unsupported/unknown route without metadata | A legacy session targeting an unsupported/unknown route with SQLite `session.thinkingMode` but no `thinking_route` metadata validates the candidate during `TurnRouteState.effectiveThinkingMode`, records bounded correction, and admits the turn as provider default (`null`) rather than leaking stale state into rejection |
| Corrected/default preference resurrection prevention | `recordCorrection` without route arguments removes the active compound route key from `routePreferencesKey`; `revalidateForRoute` and public `revalidateAndApplySession` with `selectionId: null` and `restorePreserved: false` deliberately set provider default, clear persisted session modeling in SQLite, and do not reinject `session.thinkingMode` or resurrect preserved route preferences. On the session's own route, when the active stored preference belongs to that same route, a differing SQLite `session.thinkingMode` (including a row-only clear) is the newer write and stays authoritative in `TurnRouteState.effectiveThinkingMode`; a superseded stale stored entry is still corrected. Route-keyed restore applies only when the turn targets another route or the session route moved without a thinking sync |
| Auto-failover thinking inheritance & runner profile refresh | When attempt 1 fails and auto-failovers to a candidate provider, `ThinkingRouteSessionSync.revalidateAndApplySession` routes through the same-route legacy branch: supported inherited choices survive onto candidate, unsupported candidates become provider default without spurious correction, and pre-stored candidate preferences (including provider default) win over inherited modes; SQLite `session.thinkingMode` and `ThinkingRoutePreferenceStore` persist the admitted candidate state. In `AgentRunner`, `_turnCapabilityProfile` refreshes for the candidate route mid-flight so that attempt 2 wire request options dispatch the candidate's authentic thinking directive, thinking mode, and image support while preserving same-route multi-step profile freezing |
| Route-checked profile reuse & interrupted retry wake | Profile reuse in `_requestOptionsForTurn` requires matching trimmed provider instance ID and model ID on both sides, and that method may move `_turnCapabilityProfile` to another route only inside an admitted turn (option queries after a completed turn never rewrite it). When retry wait wakes due to an external route change, `AgentRunner` synchronizes session thinking mode and refreshes `_turnCapabilityProfile` for the new session route, dispatching the switched route's authentic directive, thinking mode, and image support on attempt 2. A wake that leaves provider and model unchanged (manual retry, queued handoff, timer abort) keeps the admitted profile frozen even if capability config changed during the wait. After failover the candidate profile also drives user-attachment projection text and `ToolContext.imageSupport` |
