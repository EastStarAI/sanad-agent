# Provider-Aware Thinking Mode QA

## Scope

Validates that thinking controls are model-route scoped, fail closed for unknown
routes, and never silently ignore an explicit unsupported selection.

## Matrix

| Scenario | Expected |
|---|---|
| OpenAI reasoning model (`o3`) with selection `high` | Chat Completions body includes top-level `reasoning_effort=high`; sync/stream parity for non-stream fields |
| OpenAI non-control model with explicit selection | Typed rejection before HTTP; zero provider requests |
| Null / cleared selection | Provider default by omission; no invented `balanced` at the wire, and no provider-instance capability lookup is required for deterministic/standalone routes |
| Capabilities switch from legacy to `thinking_mode_source=model` on an unchanged route | Composer reloads the model snapshot immediately instead of remaining `Unavailable` |
| Legacy thinking controls in an isolated composer | Legacy list remains renderable without requiring model-scoped `SessionCubit` context |
| Legacy `fast`/`balanced`/`deep` when mapped option exists | Migrates to `low`/`medium`/`high` only when present in descriptor |
| Legacy alias when mapped option missing | Cleared with correction reason `thinking_option_unavailable_for_route` |
| Anthropic manual vs adaptive model | Manual emits `budget_tokens`; adaptive emits `thinking.type=adaptive` + effort; never both |
| Budget option metadata (Anthropic manual, Gemini budget, declared `anthropic_budget`/`google_thinking` budgets) | Every advertised budget option publishes the exact positive `budget_tokens` the route resolves for it, from the owning catalog's own budget authority (or its validated declared value); Off, effort/level/toggle options and unknown counts publish none |
| Explicit Anthropic budget that fits below the request `max_tokens` | The selected budget is emitted verbatim as `thinking.budget_tokens`; no remap |
| Explicit Anthropic budget the request `max_tokens` cannot honour | Actionable rejection while the body is built (`ThinkingWireSerializationException`), zero provider requests; the budget is never silently replaced by `max_tokens - 1`. A declared ceiling of `1`, `0` or a negative value leaves no room for any positive budget and is rejected the same way, while an absent `max_tokens` leaves the selected budget unchanged |
| Local thinking-wire rejection reaches the runner | Blocked `invalidRequest` notice titled `Thinking option not supported` carrying the local reason; no provider-response or contact framing, no provider identity |
| Null/omitted selection with native default metadata present | Wire stays provider default by omission: no explicit request value unless an ordinary explicit selection is sent. `default_option_id`/`is_provider_default` dispatch only when that option is explicitly selected, and a Client that auto-admits its own route's known native default sends it as exactly that ordinary selection |
| Budget metadata round-trip | `budget_tokens` survives option and descriptor serialization; a non-positive, fractional, non-finite or otherwise malformed count is absent, never truncated or fabricated, and never fails the round-trip |
| Gemini budget vs level | Nested `thinking_config` uses budget or level only |
| Exact DeepSeek effort model on its evidenced native/partner Chat dialect | Enabled thinking plus documented effort; Off disables without effort; fixed reasoners expose no adjustable control and unresolved models stay `unknown`. On generic/local/custom compatible Chat only the documented positive effort subset is exposed — no native `thinking.type` envelope, no native Off and no native default |
| Aggregator OpenRouter upstream | Delegates exact model facts while keeping the aggregator `reasoning` envelope; a finite effort set declared by the gateway's own model metadata is authoritative for that exact route — see [OpenRouter Reasoning Discovery QA](openrouter_reasoning_discovery_qa.md) |
| GLM hybrid versus forced effort | GLM-4.5/Air permit On/Off with provider-managed hybrid default; GLM-5.3 permits low/high/max with default max and rejects Off; Kimi XOR wire remains unchanged |
| Ollama missing probe versus valid negative probe | Missing/malformed evidence is `unknown`; a valid capability list lacking `thinking` is `unsupported`; no name-based options |
| Ollama Boolean declaration | Exactly declared On/Off choices and member Boolean default; sync/stream `think` remains Boolean; omitted Default emits no `think` |
| Live native evidence older than the 5-minute TTL | Validated On/Off/default facts are retained under the matching route/config revision: On sends `think: true`, Off sends `think: false`, Default omits `think`; no degradation to unknown or rejection |
| Explicit probe failure or stale cache on a native route | Resolution stays `unknown` and explicit selection is rejected with `thinking_capability_unknown`; aged evidence never bypasses failure/invalidation markers |
| Config or credential revision change with aged native facts | Cached descriptor is invalidated, the fresh revision is reassembled, and selection is rejected while that revision has no native evidence |
| Failed refresh then config/credential revision change | Failure provenance is not cleared by the revision alone; resolution stays `unknown` and selection is rejected |
| Successful live refresh after a failed probe | Failure provenance is dropped, `source` returns to `live`, and On/Off/default resolve with typed native wire |
| Typed thinking-selection rejection at turn admission | Terminal error response delivered only after the owned work item commits `cancelled`, then the turn completes normally; unrelated queued work stays `queued` and restorable |
| Stale rejection whose work item already lost ownership | No terminal response, no in-flight clear, no turn-completion signal (no busy release or queued-work drain); the newer durable owner, its bound identity, and its queued work are untouched |
| Ollama level declaration | Exactly declared native string choices/default; a native string `off` stays a string, not Boolean `false` |
| Malformed native values/default or untyped capability list | No fabricated options/defaults; unresolved evidence stays unknown |
| Codex exact native metadata | `supported_reasoning_levels` and optional member `default_reasoning_level` survive discovery/cache/resolution; malformed or foreign-model metadata is not finite evidence |
| Valid native levels without a default | No guessed first/medium default on either side; an unselected Client control stays unselected and the wire remains omission |
| GPT-5.6 Sol `none` versus Default | `none` is an explicit Off effort; Default omits the field; Astra does not acquire unsupported `none` |
| Custom / generic compatible route without exact model evidence or declaration | `unknown`; no selector inventing OpenAI effort |
| Compatible route with exact evidenced Kimi model | On the evidenced native/partner dialect the model-owned finite Kimi controls apply (K3 positive efforts; K2.6 toggle); a toggle-only family on a generic/local/custom Chat wire stays `unknown` because that wire evidences no such envelope, and an explicit validated declaration is required there; fixed models unsupported; aggregator retains its route-owned envelope |
| Every registry/factory kind | Automatic evidenced/unknown/unsupported expectations plus finite declaration, actual-mode and default-omission checks; no claim that registry coverage proves every upstream model |
| OpenCode Go model outside the exact evidenced ids | The template's registered generic effort policy publishes only exact-model-owned facts: a model without its own evidence advertises no tiers, and no family-level recognition or guessed ladder promotes it |
| OpenCode Go exact DeepSeek V4.1 Flash (`deepseek-v4.1-flash`) | Exact model-owned DeepSeek facts override the Go generic effort policy: selector visible with `Off`/`Low`/`High`/`Max` and default `High`; `off` sends disabled thinking with no effort, `low`/`high`/`max` send enabled thinking plus that exact `reasoning_effort`; an empty/null selection sends neither field; the wire keeps the exact model id |
| DeepSeek documented effort remaps | `minimal`/`medium`/`xhigh`/`ultra` are never visible tiers and are rejected as selections (`optionUnavailable`) instead of being relabelled |
| DeepSeek V4.1 near-IDs (`deepseek-v4.1-flash-x`, `deepseek-v4.1-flash-thinking`, `deepseek-v41-flash`, `deepseek-v4-1-flash`, `deepseek-v4.1`, casing variants) | Remain unevidenced: Go keeps its generic result, the client keeps a visible disabled no-control/unknown chip, and a selection is rejected before HTTP; no family/prefix/substring rule may promote them |
| OpenCode Go unknown model with `supports_reasoning_output=true` | Control remains unavailable; reasoning output alone does not invent selectable effort |
| Explicit empty `thinking_mode` session preference | Client transmits the present empty field; daemon clears persistence and emits `thinking_mode: null` |
| Client `thinking_mode_source=model` | Composer uses model/`thinking_control` options only; empty list does not fall back to `balanced` |
| Client exact model descriptor identity | Resolves thinking descriptors using exact model ID; preserves catalog namespaces (`VendorA/model` vs `VendorB/model`), case (`CaseModel` vs `casemodel`), and variant markers (`~`, `:`); strips only transport-owned provider-instance prefixes (`provider-1/`) with exact boundaries |
| Client unsupported descriptor | Visible, disabled `No control` chip; no menu is offered and the chip never claims the model cannot reason |
| Client initial descriptor load | Shows `Loading...` until the authoritative snapshot arrives |
| Client authoritative unknown descriptor | Visible, disabled `Not reported` chip; does not invent selectable controls, never renders a level or a synthetic `Default`, and is never conflated with the `Unavailable` transport state |
| Route revision mismatch | Stale session descriptor ignored |
| Explicit model refresh on mounted route | Composer updates options, default, and capability revision without route change or restart |
| Model refresh invalidating current selection | A valid explicit choice is retained; an invalid or removed selection is repaired only to the route's known valid native default, or cleared to no selection when the refreshed route declares no default. The control never disappears |
| Model refresh removing descriptor or marking unsupported | Transitions visibly to the disabled `Not reported` (removed evidence) or `No control` (unsupported) chip; the control never disappears |
| Failed, late, or cross-device model update events | Retains prior validated authority on failure; ignores foreign device/provider events |
| Model/provider switch invalidating selection | Preference cleared + correction event |
| Daemon restart with queued turn | Revalidates persisted selection before provider call |
| All 16 shipped kinds, real adapter wire (`provider_kind_wire_matrix_test.dart`) | Each kind: authoritative descriptor status/kind; the advertised option set must match an independently written expectation set exactly; **every advertised selection** (effort, budget, level, toggle) is dispatched through runtime-selected production adapters over mock HTTP (the fixture mirrors the runtime's own adapter selection instead of invoking the factory) and its exact semantic value is asserted in the captured body with independent expected facts — Chat `reasoning_effort`, Responses `reasoning.effort`+`summary`, Messages `thinking`/`budget_tokens`/`output_config.effort`, nested `extra_body.google.thinking_config.thinking_budget|thinking_level`, aggregator `reasoning.enabled|effort|max_tokens`, native `think` (Boolean and string) — plus documented absent paths; a missing expectation, a wrong value or an extra/missing advertised option fails; default omission emits no control value (the documented Responses `summary: auto` display option is the only retained fact); a non-advertised selection is rejected instead of clamped |
| Generic/local/custom compatible Chat with an exact evidenced model | Intrinsic documented standard efforts survive without a native envelope: exact DeepSeek/Kimi positive effort subsets use `reasoning_effort`; no native Off/default or ZAI envelope is invented. First-party/verified partner routes retain their evidenced native wire. NVIDIA uses its separate hosted NIM per-model contracts; see [NVIDIA Thinking Wire QA](nvidia_thinking_wire_qa.md). Synthetic carrier models prove transport, not hosted model availability |
| Custom route, model-only declaration per API mode | `openai_chat_effort` and `toggle_effort` declarations reach the Chat body; `anthropic_adaptive` reaches the Messages body; a declaration whose wire is incompatible with the actual mode resolves `unsupported` with no options |
| Gemini unevidenced ids (`gemini-3-pro-preview-fake`, `gemini-3-ultra-beta`, `GEMINI-3-PRO-PREVIEW`, `gemini-2.5`, `gemini-2.5_flash`, `models/gemini-3.6-flash`, `untrusted/gemini-3-pro-preview`) | `unknown` on the `gemini` route with no options; selection rejected with `thinking_capability_unknown`; never a fabricated level/budget control |
| Gemini aggregator delegation (`openrouter` / `google/<id>`) | Grounded `google/gemini-2.5-flash` keeps the aggregator `reasoning` envelope; `google/gemini-3-pro-preview-fake` and casing variants stay unknown |
| Grounded Gemini ids and namespace | only the exact ids listed in the per-model row below resolve, and the `google/`-namespaced equivalent of each is grounded with the same set/default; `gemini-1.5-pro` stays `unsupported` |
| Failed model-list refresh with a persisted supported model-owned descriptor | Reconstruct under current configuration/mode/revisions; only matching supported `profile`/`config_override` facts survive (cache row remains `cache_stale`). Endpoint-declared controls are route-owned and become unknown until successful discovery revalidates them |
| OpenRouter disable envelope | Admitted zero Google budget, typed false toggle and canonical effort `none` serialize as `reasoning: {"effort": "none"}` without contradictory `enabled: true`. Google level `off`, malformed effort/level, negative Google budget, non-positive Anthropic budget and unsupported directives reject before dispatch instead of being dropped. Positive admitted values keep their exact nested fields; Default omits `reasoning` |
| Declared Google levels and zero budget | Canonical `minimal` parses from the shared level vocabulary. Declared zero budget resolves to `GoogleBudgetDirective(0)`, reaching `extra_body.google.thinking_config.thinking_budget: 0` on Google and the documented disable envelope on the aggregator, never an invented `thinking_level: off` |
| Declared known defaults and Boolean kwargs semantics | Config and endpoint defaults remain descriptor metadata; null/empty/whitespace selection omits even with `default_option`, while an explicitly selected default dispatches exactly. Boolean kwargs declarations reject both Boolean values behind canonical effort-tier labels; genuine on/off and exact supported effort mappings retain meaning |
| Failed model-list refresh with live-probe-derived evidence | Descriptor becomes `live_probe_failed` `unknown` and selection is rejected with `thinking_capability_unknown` until a successful refresh rebuilds it |
| Grounded Gemini facts (per model) | each retained id exposes its own documented finite set and default from the official thinking table, verified through descriptor plus actual `extra_body.google.thinking_config` wire: `gemini-4-argon` and `gemini-3.8-flash` `Low`/`Medium`/`High` (default `Medium`, `minimal` errors on 3.8), `gemini-3.6-flash` and `gemini-3.5-flash-lite` and `gemini-3-flash-preview` include `Minimal` (defaults `Medium`, `Minimal`, `High`), `gemini-3.1-pro-preview` `Low`/`Medium`/`High` default `High` (every one of its three documented values proven in the actual Chat body), `gemini-3-pro-preview` `Low`/`High` default `High`, `gemini-2.5-flash` `Off`+budget tiers, always-on `gemini-2.5-pro` without `Off`, and both 2.5 models omit a default |
| Gemini ids without an obtained per-model set/default | `gemini-3-flash`, `gemini-3.1-flash`, `gemini-3.1-flash-lite`, `gemini-3.5-flash`, `gemini-pro-latest`, `gemini-3.8-pro` stay `unknown` with no options on the `gemini` and aggregator routes; a selection is rejected |
| Documented selection ids are never silently remapped | Selecting the advertised Gemini `minimal` level reaches the wire as `thinking_level = minimal`; legacy alias migration applies only to ids the route does not advertise |
| Ungrounded Gemini ids | `gemini-3-flash`, `gemini-3.1-flash`, `gemini-pro-latest`, `gemini-3.8-pro`, `gemini-3-ultra-beta`, `GEMINI-3-PRO-PREVIEW`, `models/gemini-3.6-flash`, other namespaces stay `unknown` on the `gemini` and aggregator routes with no options, and a selection is rejected |
| Grounded xAI Grok facts | `grok-4.5` exposes `Low`/`Medium`/`High` with default `High` and no `Off`; `grok-4.6`/`grok-4.7` add `xhigh`; each selection reaches Chat `reasoning_effort`; `grok-4.5-mini`, `GROK-4.5`, `xai/grok-4.5`, `grok-4.20-0309-reasoning`, `grok-4.3` stay unknown |
| Grounded `gpt-oss` facts (intrinsic, no allowlist) | exact `gpt-oss-120b`/`gpt-oss-20b` (and NIM's `openai/gpt-oss-*`) expose `Low`/`Medium`/`High` on Chat `reasoning_effort` on every compatible Chat mode — `openai`, `nvidia`, `lm-studio`, `llama-cpp` and a custom OpenAI-compatible route — with no family default; the same ids on an Anthropic-protocol custom route or the Codex Responses route advertise nothing; near misses (`gpt-oss`, `gpt-oss-120b-turbo`, `GPT-OSS-120B`) stay unknown |
| Failed refresh, unchanged authority | A cached `supported` model-owned descriptor is re-derived from current authority under the same revision, so the documented controls survive a transient endpoint failure and still resolve to their typed directive |
| Failed refresh after override removal, revision change or mode change | The removed/changed model-only override, a bumped config revision, or an incompatible route/API mode fails closed (`live_probe_failed` unknown) instead of resurrecting stale controls; the reconstructed-offered descriptor is never re-advertised |
| Failed refresh with authoritative failure or live evidence | Already-invalidated descriptors (`live_probe_failed`, `cache_stale`) and native/live probe descriptors stay `live_probe_failed` unknown until a successful refresh |
| Failed refresh with endpoint-declared controls | a control declared only by the endpoint's own discovery metadata is route-owned evidence and is never reclassified as intrinsic support: it becomes `live_probe_failed` unknown until a successful refresh revalidates it |
| Failed refresh with a changed credential revision | a bumped credential revision fails closed exactly like a config revision change; the stale supported descriptor is not retained |
| Client provider-default disclosure (Plan 77 / Task 77K) | The thinking menu offers exactly the declared native options and no synthetic `Default` row or chip. The declared native default is disclosed only as a provider-default hint line below its own row inside the expanded menu, next to any budget annotation that row declares; the closed chip, the persistent interface and every other row show no such claim. An exact declared option id — including a reserved-looking string — always dispatches itself |
| Client display order | The menu renders the declared choices strongest-first, i.e. the declared order reversed for display only: exact native ids, the finite option set, dispatch values and native metadata (including a legacy device list) are unchanged, and no strength ladder, sort heuristic or provider remapping is introduced |
| Client route without thinking transport | `supports_thinking_mode_change=false`, or a legacy-mode device whose `thinking_modes_list` is empty, renders a visible disabled `Unavailable` chip and offers no menu; the control is never removed from the composer |
| Client provider-default entry (removed by Plan 77 / Task 77K) | The thinking menu offers exactly the declared native options and no synthetic `Default` row or chip selection. The declared provider default survives only as the menu-only hint row annotation described above. An exact declared option id — including a reserved-looking string — always dispatches itself |
| Client known native default auto-admission | With no valid explicit choice, the route's declared default that still matches a current declared option is admitted as that option through the real composer selection path and sent as that exact value; the chip and checked row name it like any other option |
| Client declared default unknown or absent | Nothing is selected and nothing is dispatched: the menu stays open and unselected behind an honest localized prompt, with no guessed tier and no fabricated `Off` |
| Client explicit choice versus the declared default | A valid explicit choice, including an exact `Off`, always wins; resolution never overwrites it and never re-dispatches an already admitted value |
| Client route/conversation isolation | A route or conversation change never writes another route's or conversation's value; a superseded snapshot response dispatches nothing, and only the resolved current route admits its own native default |
| Client same-route conversation switch | A newly selected conversation on an unchanged route admits its own declared native default when it has no valid explicit choice, while a conversation holding a valid explicit choice (including `Off`) keeps it and never receives its sibling's admitted value. The write is dispatched only under the composer's own active-conversation ownership, so a composer that has not adopted the new conversation yet writes nothing and defers to its own ownership change |
| Client token-budget preset without a declared count | The menu annotation still identifies the preset as a token budget; no token value is invented and no effort-like label stands alone for it |
| Client fractional declared budget (`budget_tokens: 1024.5`) | Parsed as absent metadata, never truncated to `1024`, and never re-serialized as a real count |
