# Bundled Product Skills QA

## Scope

This matrix verifies the product-managed skills shipped inside the standalone
Sanad Agent executable. It covers the same lifecycle for source, installed,
worktree, and test runtimes while keeping each runtime inside its active
`SANAD_HOME`.

## Build and provenance matrix

| Scenario | Expected result |
|---|---|
| Product manifest contains the three approved skill ids | Generation includes only `skill-creator`, `find-skills`, and `agent-browser`. |
| A developer-only repository skill is present but absent from the product manifest | It is not represented in the generated bundle or extracted user tree. |
| Duplicate id, missing `SKILL.md`, missing license, missing executable declaration target, absolute/traversal path, symlink, or unsupported entity | Validation fails before compilation. |
| Generator runs twice against unchanged sources | Generated bytes and bundle revision are identical. |
| Imported source package comparison | Every selected source file and required license matches its pinned reviewed revision. |
| CI or release checkout has stale generated output | The generated-drift check fails before analysis or compilation. |

## Installation and discovery matrix

| Scenario | Expected result |
|---|---|
| First run with an empty Home | All three complete packages and the managed-state file appear under `SANAD_HOME/skills`. |
| Multi-file skill installation | References, scripts, assets, viewer files, and license retain their relative paths; declared executable intent is applied on Unix. |
| Source execution | The active source process installs into its configured `SANAD_HOME`, not into the repository or an unrelated user Home. |
| Linked-worktree execution | The skills are installed only in the worktree-scoped Home. |
| `SkillRegistry` receives distinct `SANAD_HOME` and `HOME` | The Sanad Home skill wins the user Sanad-skill lookup and is discoverable. |
| Workspace defines a same-name skill | Existing workspace precedence remains unchanged and shadowing is reported by normal registry behavior. |

## Update and removal matrix

| Scenario | Expected result |
|---|---|
| Bundle revision matches installed state | Startup takes the fast path without enumerating or hashing skill content. |
| Bundle revision changes and managed content matches its recorded origin | Changed package is replaced, newly selected package is installed, and state advances only after success. |
| Managed package was edited by the user | User content survives; product ownership is relinquished and later updates do not overwrite it. |
| A different untracked package already uses a newly bundled id | It survives and is never baselined as managed. |
| User deleted a managed package | A later reconciliation records the deletion and does not silently restore it. |
| Product manifest removes an unchanged managed package | Its directory is deleted and its state entry is removed. |
| Product manifest removes a modified package | Its directory survives as user-owned and its state entry is removed. |
| State is malformed or unsupported | Existing packages are preserved; safe missing packages may be installed only when no collision exists; state is rewritten only after successful reconciliation. |

## Failure and filesystem safety matrix

| Scenario | Expected result |
|---|---|
| Install copy fails before completion | No managed success revision is recorded; next startup can retry. |
| Update fails after the old tree is moved | The old complete tree is restored and no partial destination shadows it. |
| Process stops between per-skill progress and final revision | The empty/incomplete revision forces a safe idempotent retry. |
| Destination or child is a symlink | Reconciliation rejects it and leaves external targets untouched. |
| Delete target is Home, skills root, filesystem root, or sibling | Strict-child validation rejects the operation. |
| State write fails | The bundle revision does not advance; the next start reconciles again. |
| Reconciliation throws during normal startup | The agent emits one content-free warning and continues startup. |

## Standalone release matrix

For every supported Agent platform, release CI runs the newly compiled artifact
with a temporary Home before signing/publication where applicable.

| Platform | Evidence |
|---|---|
| macOS arm64/x64 | One copied executable runs and extracts all required sample files without source or sidecar assets. |
| Linux x64 | One copied executable performs the same offline extraction. |
| Windows x64 | One copied `.exe` performs the same extraction using the temporary Home and owner ACL boundary. |

The smoke check requires at least the main file from every selected skill, one
nested reference from the multi-file package, and each copied license. Unit
coverage additionally decodes every embedded file and verifies its SHA-256.

## Performance acceptance

An unchanged startup reads only the small managed-state file and compares the
compiled bundle revision. It does not decode compressed files, walk directories,
or compute content hashes. Full reconciliation is limited to first run, missing
or corrupt state, and a changed product bundle revision.
