# Task 89j: إكمال Standalone وتقوية أتمتة CLI

## الهدف

جعل `sanad run` وواجهة CLI قابلة للاعتماد من الطرفية وGitHub Actions دون Flutter Client أو خدمة Daemon مسبقة، مع إعادة استخدام محرك سند ومُلّاك الحالة الحاليين داخل العملية، ومنع تنافس SQLite، وضمان مخرجات آلة نقية وإلغاء ومهلة واختبارات إصدار حقيقية.

## القرارات المثبتة والنطاق

- الوضع الافتراضي يتصل بالـDaemon القائم عند اكتشافه.
- `--standalone` يركّب محرك سند الحالي داخل عملية CLI؛ لا ينسخ المحرك ولا يشغّل Daemon مؤقتًا أو يفتح منفذًا محليًا.
- Standalone يرفض البدء إذا كان Daemon آخر يملك نفس Sanad Home، بدل فتح اتصال SQLite منافس.
- بيئات CI تختار Sanad Home معزولًا وتضبط المزود عبر الأسرار أو مزود E2E الحتمي في الاختبارات.
- التغطية الرسمية تشمل GitHub Actions وأمثلة Shell عامة قابلة للتكييف.
- CLI محلي في هذا الإصدار؛ `--device` ليس عقد توجيه لجهاز بعيد ولا يظهر ضمن خيارات `run` أو `chat`.
- الوضع غير التفاعلي يرفض الموافقات الحساسة افتراضيًا، ولا يسمح بها إلا بخيار خطر صريح وموثق.
- `--json` يطبع envelope نهائيًا واحدًا صالحًا للتحليل. JSONL streaming ليس ضمن هذا الإصدار.
