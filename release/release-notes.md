# Sanad 1.0.21

Sanad 1.0.21 restores iOS sign-in and turns unattended work into a first-class surface: schedules and user secrets now have real screens, provider setup explains a rejected credential instead of echoing a response body, and a delegated turn survives a daemon restart instead of being reported as failed.

## Sign-in and iOS

- **Sign-in works on iOS again.** Every TestFlight build returned `303 /oauth/ios/callback-failed` and *Authentication return failed*, because the app never claimed `applinks:app.sanad.eaststarai.com`. Two independent defects caused it: the iOS job exported an unsigned archive, and `xcodebuild -exportArchive` re-signs such an archive from the profile alone and drops the app's own entitlements; the `Sanad App Store` profile also predated the Associated Domains capability. Mobile authorization additionally opened an in-app browser view, which never hands a Universal Link back to the app. Mobile authorization now always opens the platform's external browser, the App ID capability is granted and the profile regenerated, the app adopts the `UIScene` life cycle the current iOS SDK requires, and one script owns the iOS binary for both the release pipeline and Internal TestFlight (#333).
- **The signed IPA is verified before it can ship.** `client/release/ios/build_signed_ipa.sh` performs one signed `flutter build ipa --export-options-plist` and then fails the job unless the exported app claims every host in `client/ios/Runner/Runner.entitlements`, its embedded profile grants the capability, and that profile is the one the export options name. Both workflows delegate to it, so the private release artifact and the TestFlight artifact are the same binary produced the same way; Runner-only signing keeps beta and on-device profiles installable (#334, #335, #336, #342). The iOS build in this release was installed on a physical iPhone, launched, and completed Portal sign-in.
- **The device list recovers after signing in.** Completing sign-in on iOS used to leave the device inventory empty for about 24 seconds and show a *No Agents Found* chip while the onboarding route stayed reachable. The resume-driven reconnect tore down the socket the post-sign-in connect had just authenticated, so the first inventory request went onto a dead socket and waited out the 10-second connect timeout. `reconnect()` now reuses a live, authenticating, or in-flight connection, an empty list counts as authoritative only after a `get_devices` reply actually lands, and the surfaces show a localized loading state instead of an English literal (#342).

## Schedules

- **Schedules have a screen.** A schedule can be created, inspected, paused, resumed, run immediately, edited, and deleted without starting a conversation first. The list shows the recurrence summary, the next run in the schedule's own time zone, the last outcome, a paused pill, and a failure badge; the detail screen carries **Details** and **Run history**, where each run reports its status, trigger, duration, its own bounded error, and an **Open conversation** action that lands on the run's user message when one exists (#312, #326, #328).
- **The editor previews the recurrence before it is saved.** Once, interval, daily, weekly, and monthly recurrences are edited with their own fields, an advanced zone override, a workspace chip, and a model chip reused from the composer. A debounced `schedule.preview` renders the next fire times in the selected zone and states an invalid expression in place, so a schedule is never created with a rule the user could not read (#328).
- **A conversation that owns schedules says so.** Conversation rows carry a schedule marker, and deleting such a conversation warns that its schedules depend on it — they are paused, not silently lost (#328).
- **Scheduled work is always its own turn.** A schedule dispatch is a new turn: immediate when the conversation is idle, queued behind the active turn when it is busy. It is never injected as a mid-turn steer, which commits no root user message and would hide the run from history (#321).
- **A continuous schedule keeps one conversation.** A user-owned `continuous` schedule used to open a new conversation on every fire, because dispatch used the record captured when the timer was armed while the created conversation id was written straight to the row. Dispatch now re-reads the row, so fires 2 and 3 land in the conversation fire 1 created (#329).
- **Run history can anchor on its own message.** `schedule.runs` now exposes the `history:<sessionId>:<rowId>` anchor the conversation loader accepts, so **Open conversation** opens at the run instead of at the tail (#329).
- **`schedule_task` can be managed from a tool call.** The Agent tool gained `pause`, `resume`, and `run_now`, plus an optional `name` on create and update, on top of the scheduler control layer and its typed refusals (`schedule_not_found`, `schedule_permission`, `schedule_expired`, `schedule_orphaned`) (#317, #321).
- **Runs are recorded, not inferred.** A `running` row is written before the event is dispatched, a missed window beyond its grace is recorded as `skipped`, completion is correlated by request id, a run interrupted by a daemon restart is reconciled as `interrupted` instead of staying `running` forever, and three consecutive failures flag `suggest_pause` (#317).

## Secrets

- **There is a place to store credentials an agent needs.** **Settings → Privacy & Security → Secrets** lists what is stored, adds a value, replaces a value without ever reading the old one, and deletes with confirmation. Rows show the name, an optional description, the updated date in the client locale, and whether the user added the secret or the agent requested it (#315, #318, #323, #324).
- **Values are write-only by construction.** The only copy of a value lives in the dialog's text controller, which is cleared before the request is awaited and disposed with the dialog; the protocol offers `secret.set`, `secret.delete`, and `secrets.list` with no read command; a canary test scans every state the cubit emits after a submit. A replaced value opens with an empty field and the sentence stating that the saved value is never shown (#318, #324).
- **The agent can ask for a secret instead of failing.** A secret acquisition hook resolves a missing value from the user's catalog and records its source, so a request that needs a credential names the secret it needs rather than ending in an unexplained failure (#315).

## Provider setup

- **A rejected credential is explained, not echoed.** A `401` during model discovery used to leave the instance in `draft` and surface the provider's raw response body in the model picker. One sanitized owner now carries a category, the HTTP status, a short canonical reason, and an endpoint reduced to `scheme://host[:port]/path` — never a credential, a header, a request payload, or a raw body. `401`/`403` report `needs_auth`, other definitive failures report `error`, and only failures that prove nothing about the credential keep `draft`. The instance card, the credential form, and the CLI all read that cause, and a new instance cannot reach model selection with a rejected key (#346).
- **Testing a provider proves it twice.** `provider.instance.test`, setup verification, and the CLI share one verifier: a verified live discovery *and* one minimal generation probe (short prompt, at most one output token, short timeout, no tools, no retries, never persisted). **Test** therefore reports the verified model count and the probe's round-trip, or the same categorized failure (#346).
- **Provider lists lead with OpenCode Go and can be searched.** `opencode-go` is declared first in the provider registry, which is the single ordering authority the CLI wizard and the Client picker both render, so no surface re-sorts it. The setup picker gained a search field with a clear action and a localized empty state that filters on display name, template id, and aliases while preserving the daemon's order (#343, #345).
- **Codex keeps its prompt-cache affinity.** Codex Responses requests carry a bounded content-addressed `prompt_cache_key`, mirrored in the ChatGPT affinity headers for both synchronous and streaming requests, so moving between Responses hosts no longer discards the provider's cache. The field is kept for xAI, which documents it, and dropped only for GitHub-hosted Responses endpoints (#356).

## Command line and runtime

- **`sanad run` no longer opens the secret vault to do nothing.** The entry point classified every `run` as "may touch a secret", so each delegated task paid three owner-index reads plus one read per indexed secret, wrote a vault warning into `secret_vault_events.jsonl`, and could block on a macOS authorization dialog before dispatching a turn that reads no secret at all: a gateway run attaches to the daemon, which owns every credential, and `--standalone` already opens the vault lazily when it starts. `run` is now exempt from the eager open, opening the vault still clears the skip decision so a standalone run can write and prune, and an AOT smoke proves a gateway turn completes with no vault artifact in a throwaway Home (#350).
- **A `sanad run` turn survives a daemon restart.** A restart used to end the worker with *Gateway connection lost before turn completed* while startup recovery kept working headless, so the supervisor recorded a failure for work that was still running. The runner now spends up to `--reconnect-timeout` (default 60 seconds) rediscovering the same Home — a foreign Home still fails closed with exit 78 — then re-attaches by request lineage: it compares the durable execution snapshot's request id with the one it dispatched, re-subscribes to that turn's events, and finishes with the turn's real outcome and exit code without re-sending the brief or admitting a second turn. `--session` against a session whose turn is still owned refuses with `turn_in_flight` (exit 3) (#278).
- **An automatic retry is no longer reported as a stop.** A retryable failure published the moment its retry was scheduled as `blocked`, so `sanad run` exited 1 and the supervisor journaled a failure seconds before the daemon resumed, while `sanad session show` said `idle`. Notice payloads now carry `retry_attempt`/`retry_budget` with explicit `isAutomaticRetryPending` and `awaitsIntervention` flags: an already-scheduled automatic retry publishes `waiting` and prints `Retrying automatically in Ns (attempt n of N).`, `blocked` strictly means nothing continues the turn without an operator, and `session show` derives its status from the durable execution state instead of a stale `in_flight` projection (#297).
- **`sanad models` reports the thinking levels a route actually admits.** Each model entry now carries the stored `thinking_control` descriptor — status, options, effective default, and the authority layer that decided it — in both the human block and the `sanad.models.v1` `--json` document, additively so an entry without a descriptor is unchanged. A single-model inspection additionally prints the source, the default and its origin, and the capability revision; `unsupported` and `unknown` are stated honestly instead of as an absent badge (#279).
- **The `sanad-client` relay mirrors the Agent's grammar.** Approval and action resolve the target session with the Agent's own argument grammar, including `--run-as-user` and `--reconnect-timeout` as value options, and refuse an argument vector that names two different sessions (`ambiguous_session_target`) without relaying anything (#284, #355).

## Compaction and storage

- **Automatic compaction completes again for oneshot sessions.** A continuity anchor was built from an unanchored `RegExp('ask:\\s*(.+)')`, so `ask:` matched inside `Task:` and inside `## Blocker:` headings, captured the brief line, and then demanded it verbatim in the summary; every automatic compaction of a `sanad run` session therefore failed `continuity_validation_failed`, and the repair prompt asked for a non-schema key the strict parser rejected. Labels now own their line (start, optional markdown prefix, colon directly after the label), a value over 160 characters is report-only, each label maps to exactly one schema field, and the parser decodes the leading balanced object when a provider repeats the whole object (#352).
- **A failed compaction says why.** One durable `warning` notice — an allowlisted cause sentence with no summary or provider text — is recorded when automatic compaction fails, projected by `session.query`, and cleared by the next successful compaction, so a reconnecting Client sees why a session is uncompacted instead of a waiting clock (#352).
- **A full disk is reported as a full disk.** SQLite aborts the surrounding transaction for `SQLITE_FULL`, and the old catch block then issued a bare `ROLLBACK` that replaced the real failure with `cannot rollback - no transaction is active`; one observed session reported `database or disk is full` under a provider error title. Writes now pass through one transaction boundary that rolls back only while SQLite still holds a transaction and always rethrows the original failure, and a typed `storageFull` reason — blocked, no automatic retry, no provider failover — publishes *Storage full* without a provider response body (#354).
- **Request dumps are retained, not accumulated.** One Home held 25 900 dumps and 14 GB with no retention. A new `diagnostics.requestDumpRetentionDays` policy in `config.yaml` (positive integer, default 3 days, strictly validated) is enforced by a service that sweeps once at daemon start and then daily, deletes only `request_dump_*` and `compaction_dump_*` names inside the Home's own directory, never follows a symbolic link, skips dumps an in-flight request still owns, and logs one lifecycle line with the removed count and bytes (#354).

## Linux installation

- **A root install no longer rolls back.** The systemd unit ran as the dedicated `sanad-agent` account while `ExecStart` lived under `/root/.sanad`, so activation failed with `203/EXEC`, and the health verifier read the Local Gateway credential once with zero attempts before the daemon could write it. A root Linux install now selects `/var/lib/sanad-agent` as its Home — an explicit `SANAD_HOME` still wins, and a root Home that already carries an installed binary is kept rather than migrated — and one shared rule decides the service account for every root entry point, including `sudo -i`, `sudo bash install.sh`, and `curl … | sudo bash` (#344).
- **The installer refuses before it spends a pairing.** `sanad service install` asks the kernel the same question systemd will ask — `test -x` on `ExecStart` and `WorkingDirectory`, executed as the unit's account — and refuses before the definition is staged, naming the account, the unreachable path, and the remedy. `--run-as-user <account>` is the one explicit override, and an existing definition that names another Home stops the install with the exact removal command instead of failing after the device authorization is spent. The health check counts real attempts inside its bounded loop and reports a timeout that names the missing credential (#344).

## Client

- **The selected font applies everywhere, and the default works offline.** A font chosen in Settings only reached text that read the theme's `textTheme`; widgets that built their own `TextStyle` kept a hardcoded family across 159 call sites in 37 files, and Cairo was fetched at runtime, so the default could not render on a first launch, offline, or on web at all. One typography owner now derives every user-facing style from the theme's resolved family, machine-readable text keeps the single `firaCode` monospace constant, and Cairo ships bundled with its OFL licence as the default for a profile with no saved preference. A guard fails on any new `fontFamily:` literal or direct `GoogleFonts.<family>(` call outside the theme (#349).
- **Dictated text survives a pasteboard restore.** A dictation tool posts Cmd+V and restores or clears the pasteboard immediately afterwards, and the composer read the clipboard after the key event, so the transcript was replaced by the restored content or lost. The macOS runner now reads the pasteboard at the key event, forwards plain text on its own channel, and inserts it once at the caret; a pasteboard carrying a file or an image still routes to the attachment path, and only a plain Cmd+V in the app's own key window is handled (#341).

## Workspaces

- **A workspace folder can be changed from any online device.** Renaming or deleting a folder that is or contains a registered workspace is refused as `workspace_in_use`, so a user could create a remote folder but not make an existing workspace follow it. **Change Path** is now offered for every online device and reuses the existing confined browser instead of adding a second picker; the same-desktop local picker is unchanged (#331).

## Developer tooling

- **`sanad-dev inventory` shows what actually exists.** One read-only projection lists worktrees with their derived and recorded Home, runtimes with ports, pids, lease source commit and attached Clients, every discovered Client with its lease ownership and `lease-pid-drift`, Test Homes, and the orphans — dev Homes with no worktree, runtime records whose worktree or launcher is gone, and stale gateway endpoint records — each with the exact cleanup command. The reference host held 20 worktree Homes and 37 runtime records for 6 worktrees, and nothing reported which were orphaned (#281).
- **Warm `sanad-dev ui` invocations cost less.** The fixed per-invocation cost was cut without changing any action's behavior (#274).
- **A delegated worker that dies mid-turn no longer takes the verdict with it.** After a worker exits, the supervisor probes the session and records a fifth state, `following`, when the daemon still owns the turn; it then polls the durable state, mirrors `needs_input`, `needs_permission`, `blocked`, `waiting`, and `resuming`, and settles the task with the turn's real outcome and an explicit result source. Cancelling a followed task stops the daemon session, and a worker is spawned as the leader of its own process group so a cancel reaches the real process instead of an `fvm` wrapper (#267, #280).

## CI and release

- **Public CI is 2.3× faster at unchanged coverage.** Client and Agent tests run in shards, independent checks run in parallel, and the Flutter SDK is no longer installed twice while `PUB_CACHE` sat uncached; the workflow wall time fell from 607 to 265 seconds and `setup-fvm` from 75–233 to 18–29 seconds per job (#348).
- **Protected review labels are re-verified on demand.** Applying labels created one skipped workflow run per label event, so every pull request accumulated four to six empty runs. The verification is now dispatched with `workflow_dispatch` and a `pr_number` input; it re-reads the labels unconditionally, so a *removed* protected label turns the gate red on the same dispatch, and a fork pull request no longer needs a manual job rerun (#347).
- **Production asset jobs run in one deterministic order.** In 1.0.20 the `web`, `updates`, and `installers` jobs ran in parallel on one host, and the `installers` health sweep treated the `updates` container's restart as an outage and rolled back. The jobs are now serialized as `updates` → `web` → `installers` with explicit skip and failure propagation, and activation and rollback verification use a bounded per-endpoint retry window, so a container restart blip cannot trigger a rollback while a real failure still fails closed (#277).

## Internal maintenance

No user-visible behavior changed in these changes: the largest single-responsibility splits landed with characterization tests and schema snapshots that pin the previous behavior — the supervisor, session, workspace, provider, state, and configuration modules, `driver_main.dart`, the settings pages, the MCP screens, and the conversation input composer and tile widgets (#285–#320).

This release was built from tagged public source by the protected Sanad release workflow. Verify downloads against `SHA256SUMS`, `release-manifest.json`, and GitHub build provenance before installation.

> [!WARNING]
> **Unsigned Windows build:** Sanad Agent and Sanad Client `1.0.21` artifacts for Windows x64 intentionally do not carry Authenticode signatures. Windows Defender or SmartScreen may show an unknown-publisher warning. Download only from this official `EastStarAI/sanad-agent` release, verify the manifest, file size, SHA-256, and GitHub provenance, and do not disable platform protection. Windows release gates run on Windows 11; Windows 10 has not been validated. The Client update package remains signed separately with WinSparkle DSA; that update signature is not Authenticode and does not establish a Windows publisher.

macOS and Android artifacts use their documented platform signatures. Linux and Windows artifacts are bound to the release through checksums, the immutable manifest, SBOM, and GitHub attestations.
